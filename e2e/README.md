# Automated Test (E2E) — Playwright

ทดสอบระบบเภสัชพร้อมสอบแบบ **Black Box** ผ่านหน้าเว็บเหมือนผู้ใช้จริง ตรวจผลจากสิ่งที่แสดงบนหน้าจอ
ชื่อเทสต์ขึ้นต้นด้วย Test ID (เช่น `EXAM-T08`) และแต่ละ `test.step` คือขั้นตอนในคอลัมน์ Test Action

## เตรียมก่อนรัน

1. เปิดฐานข้อมูล backend (`pharmacy_backend`) และ frontend (`npm run dev` ที่พอร์ต 3000)
2. คัดลอก `e2e/env.example` เป็น `e2e/.env.e2e` แล้วใส่บัญชีทดสอบ
   - `E2E_ADMIN_*` — บัญชี **Super Admin** (role 3) ใช้กับเทสต์ฝั่งผู้ดูแลระบบทั้งหมด
   - `E2E_STUDENT_*` — บัญชีผู้เรียน (role 1) ไม่ใส่ก็ได้ แต่เทสต์ฝั่งผู้เรียนจะถูกข้าม
   - `E2E_EXAM_BANK` (ไม่บังคับ) — ชื่อชุดข้อสอบที่ใช้ทดสอบการทำข้อสอบ ถ้าไม่ใส่จะใช้ชุดที่มีจำนวนข้อน้อยที่สุด
3. `auth.setup.ts` จะรอ backend ตอบ แล้วเข้าสู่ระบบทั้งสองบัญชีเก็บไว้ใน `e2e/.auth/` ก่อนเริ่มเทสต์อื่น

```bash
npm run test:e2e
```

```bash
npx playwright test ts-exam --headed
```

```bash
npm run test:e2e:report
```

> dev server คอมไพล์หน้าครั้งแรกช้า (บางหน้าเกิน 15 วินาที) และบางครั้งขึ้น error ของ Next.js เองระหว่างคอมไพล์ใหม่
> ถ้าต้องการผลที่นิ่งกว่า ให้รันกับ production build (`npm run build` แล้ว `npm run start`)

## ข้อมูลทดสอบ

- ข้อมูลที่เทสต์สร้างทุกชิ้นชื่อขึ้นต้นด้วย `E2E-` (หรืออีเมล `e2e-…@example.com`) และถูกลบผ่านหน้าเว็บใน `afterAll`
  ขั้นเก็บกวาดลบรายการ `E2E-` ที่ค้างจากรอบก่อนด้วย
- เทสต์ที่แก้ข้อมูลบัญชีผู้เรียน (เช่นนามสกุล) คืนค่าเดิมเสมอ
- ผลสอบ ผลทบทวนประจำวัน และรายงานปัญหาข้อสอบ (ปิดสถานะแล้ว) จะคงอยู่ในประวัติของบัญชีผู้เรียน
- กลุ่มที่เคสต่อเนื่องกัน (สร้าง → แก้ → ลบ) ใช้ `mode: 'serial'` เพราะเมื่อเคสล้ม Playwright จะเริ่ม worker ใหม่และสุ่มรหัสรอบใหม่
